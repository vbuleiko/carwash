# CLAUDE.md — память проекта Washbook

## Пользователь и как с ним работать
- Пишет по-русски, отвечать по-русски. На этапе планирования просил отвечать **кратко**.
- Требование к продукту: «супер минималистично и удобно». Не раздувать функции, лишнее не добавлять без спроса.
- Бизнес в **ЮАР** (South Africa). Прод: виртуалка **Google Cloud** (Compute Engine), лучше регион `africa-south1` (Йоханнесбург).
- Перед большими задачами пользователь хочет, чтобы сначала задавались уточняющие вопросы.

## Продукт
Автомойки в ЮАР ведут учёт на бумаге: мойщик записывает на листке марку, номер авто и телефон клиента.
Washbook заменяет листок: машину записали → назначили мойщиков → нажали **Ready** → в WhatsApp уходит «машина готова».
Модель — SaaS-подписка для моек. Рабочее название `Washbook` (меняется через `APP_NAME`).

| Оплата мойщикам | **Не нужна** в приложении (решение 02.10.2026, убрана): мойщики — только имена и скорость |
| НЕ выбрано | Способы оплаты и сверка кассы (cash/card/SnapScan) — не делать без запроса |

### Онлайн-запись (решения 02.10.2026)
Идея: показать хозяину мойки всё (лендинг, приложение, страницу записи). Если купит — на его домене и хостинге ставится **сайт его мойки** (страница записи в выбранной теме) и приложение.
| Вопрос | Решение |
|---|---|
| Куда попадает запись | В приложение мойки: вкладка **Bookings** и полоса «Booked today» на доске. Подтверждение клиенту — кнопкой **Confirm** (wa.me, как Ready). «Arrived» открывает «New car», заполненную из записи |
| Выбор времени | Часы работы по дням + **сколько машин моется одновременно** (Settings → Online booking) + **время каждой услуги** (Price list → Takes, min). Запись держит место всё время своих услуг (целыми получасами) и должна закончиться до закрытия. Шаг 30 мин, на 14 дней вперёд, не раньше чем через 30 мин. Неподходящие времена скрыты |
| Отмена записи | Владелец: **Cancel** открывает WhatsApp с текстом отмены (настраивается в Business & messages), как Confirm. Клиент: кнопка **Cancel booking** на своей странице, пока время не прошло; у владельца видно «Customer cancelled» |
| Запись → визит | Цена в «New car» = цена из записи (даже если прайс изменился). Поменял услуги — цена пересчитывается. Тип авто из записи не перебивается историей машины |
| Страница | Шапка мойки (название, адрес, часы, WhatsApp) + форма: тип авто → услуги (несколько) → день и время → имя, WhatsApp, номер авто (необяз.), заметка. Без оплаты |
| Сайт на домене клиента | `SITE_MODE=1`: на `/` страница записи, `/app` — приложение, первая регистрация создаёт мойку, потом `/signup` и демо — 404 |
| Скан license disc | Только в приложении, на «New car»: кнопка **Scan licence disc** → камера → заполняются номер, марка + модель и тип авто. Цвет не берём. Работает на Android (встроенный `BarcodeDetector`) и iPhone (свой декодер) |

## Архитектура
Python 3.12 · Flask 3.1 · SQLite (WAL) · серверные Jinja-шаблоны + один `static/app.js` · без внешних CDN.
Прод: Docker (gunicorn `--preload`, 2 воркера) + Caddy (автоматический HTTPS). Данные в томе `/data` (`washbook.db`, `secret_key`).

```
app/__init__.py   create_app(): конфиг из env, ProxyFix, CSRF, CSP/заголовки, фильтры шаблонов
app/db.py         схема SQLite (CREATE IF NOT EXISTS; новые колонки — в CREATE TABLE и в ADDED_COLUMNS, там ALTER для старых баз)
app/owner.py      /app — доска, приём/редактирование визита, машины, отчёты, настройки
app/public.py     /, /signup, /login, /logout, POST /demo, /privacy, /robots.txt, /healthz
app/site.py       страница записи для клиентов: /book/<slug>, POST туда же, /book/<slug>/<code> — «запись принята»
app/bookings.py   часы работы, свободные времена, записи, текст подтверждения, адрес страницы (slug)
app/disc.py       штрихкод license disc (PDF417, текст через `%`) → номер, марка/модель, тип авто; список марок `MAKES`
app/admin.py      /admin — пароль из ADMIN_PASSWORD (пусто = 404)
app/queries.py    общие запросы: прайс, визиты, лояльность, тексты и ссылки WhatsApp, подписка
app/reports.py    отчёты, скорость мойщиков, заработок
app/seed.py       стартовый прайс для новой мойки, генерация демо, очистка демо
app/utils.py      время, деньги, телефоны, номера авто, wa.me
app/themes.py     список тем и выбор текущей: тема мойки → cookie посетителя → THEME; `fonts` — файлы, которые base.html предзагружает
app/assets.py     отдача /static: адрес с хешем содержимого (`?v=`), кэш на год, brotli для текста
app/static/style.css         вся вёрстка + токены темы Classic + @font-face всех шрифтов
app/static/themes/<name>.css  остальные темы: переопределяют токены и немного правил, грузятся после style.css
app/static/fonts/            шрифты тем (свои файлы, без CDN), ужаты без потерь — см. «Скорость загрузки»
app/static/vendor/           декодер PDF417 для iPhone: barcode-detector 3.2.2 + zxing_reader.wasm (MIT/Apache-2.0), как пересобрать — README.md там же
app/templates/site/          страница записи (book.html, done.html, _hero.html, _top.html — панель владельца с выбором темы)
tests/            pytest (conftest.Browser сам подставляет CSRF-токен)
deploy/           setup-vm.sh, update.sh, backup.sh
```

### Модель данных
`tenants` (мойка) → `car_types`, `services`, `prices(service_id, car_type_id)`, `washers`, `vehicles` (уникальны по `tenant_id + plate_key`) → `visits` → `visit_services` и `visit_washers`.
`tenants` → `bookings` (`slot_at` в UTC, `minutes` — время услуг на момент записи, `status`: `new → confirmed → arrived`, плюс `cancelled` и `cancelled_by` = `owner`/`customer`; `visit_id` после «Arrived»; `code` — для ссылки клиента) → `booking_services`. У `services` есть `minutes` (сколько запись держит место).
Настройки записи в `tenants`: `slug` (уникальный, адрес `/book/<slug>`), `address`, `hours` (JSON на 7 дней с понедельника, `''` = по умолчанию), `slot_capacity`, `booking_on`, `msg_booking`, `msg_cancel`.
Убранные колонки (оплата мойщиков) удаляются из старых баз через `db.DROPPED_COLUMNS`.

### Соглашения (важно соблюдать)
- **Каждый запрос фильтруется по `tenant_id`.** Для чужих id — 404. Есть тест `test_car_wash_cannot_see_another_car_wash`.
- Деньги хранятся **в центах** (int). Вывод: фильтр `money` → `R1,234` / `R120.50`. В инпутах — фильтр `amount`.
- Время: **UTC-строки `YYYY-MM-DD HH:MM:SS`** (`utils.ts()`). В шаблонах фильтр `local` переводит в пояс мойки (по умолчанию `Africa/Johannesburg`).
- Телефоны хранятся международными цифрами без `+` (`27821234567`) через `normalize_phone`. Номер авто сравнивается по `plate_key` (только A-Z0-9).
- Статусы визита: `queued → washing → ready → collected`, плюс `cancelled`. Метки времени при смене статуса выставляет `queries.status_updates` (при откате вперёд лежащие поля обнуляются).
- Скорость мойщика — среднее отношение его времени к обычному времени на ту же работу (набор услуг + тип авто). Учитываются мойки от 3 до 300 минут; показывается, если у мойщика не меньше 3 таких моек.
- Лояльность считается **по номеру авто**: `loyalty_every = 6` значит, после 5 платных шестая бесплатна; `0` — выключено.
- Все POST-запросы требуют CSRF: поле `csrf` в форме или заголовок `X-CSRF`. JS-запросы шлют `X-Requested-With: fetch` и получают JSON вместо редиректа.
- Вход: в сессии лежат `tenant_id` **и** `key` = `tenants.session_key`, `owner.load_tenant` сверяет их (id удалённых демо SQLite выдаёт заново — без ключа старая cookie открыла бы чужую мойку). Смена пароля и сброс в `/admin` меняют ключ → остальные устройства выходят. Новый вход — только через `public._start_session` / `queries.session_key`.
- Числа из форм (id, проценты) проверять `utils.is_number` (только цифры, до 9 знаков), деньги — `parse_money` (до R9 999 999.99). Иначе 500 от SQLite.
- Лимиты (`security.limiter`) хранятся в таблице `rate_hits`, общие для всех воркеров gunicorn.
- Кнопка «Ready» — это `<a href="wa.me..." target="_blank" data-mark="/app/visit/<id>/ready">`. JS отправляет POST и перезагружает доску. В демо (`data-demo="1"` на body) вместо открытия WhatsApp показывается превью.
- Демо-мойки: `is_demo = 1`, `email = NULL`. Живут 24 ч (`seed.DEMO_HOURS`; старое демо выкидывает на лендинг), не больше 300 одновременно, не больше 10 в час с одного IP. Телефоны в демо случайные, но похожи на настоящие, поэтому ссылки WhatsApp в демо — `#` (`queries.chat_link`), а JS показывает превью.
- Истёкшая подписка: данные видны, но `/app/new` не пускает.
- Вёрстка mobile-first. После изменений UI проверять ширину 390px на **горизонтальный скролл** (`document.documentElement.scrollWidth`). Скрытые input'ы уже раз ломали ширину страницы.
- Стиль кода: без лишних комментариев, короткие функции, код на английском.
- Статика: `url_for('static', ...)` сам добавляет `?v=<хеш содержимого>` (`assets.Static.add_version`), такой адрес браузер держит год (`immutable`) и не перепроверяет. `?v=` руками не дописывать. Шрифты в `url(/static/...)` внутри CSS получают хеш при отдаче. Без хеша или со старым — `no-cache`. css/js/svg/wasm/webmanifest уходят brotli, если браузер умеет (Caddy такой ответ не пережимает), иначе их сжимает Caddy. В `--debug` файлы перечитываются на каждый запрос.
- Страницы (GET, 200, HTML) получают слабый ETag и `private, no-cache`: неизменённая страница возвращается как 304 без тела. ETag слабый, потому что сильный Caddy при сжатии переписывает (`…-gzip`).
- Запись: свободное время считает только `bookings.days()` (у каждого времени `fit` — сколько минут подряд свободно до закрытия; JS прячет времена, где `fit` меньше времени выбранных услуг; сервер повторно проверяет в `free_slot()` внутри `BEGIN IMMEDIATE`, чтобы двое не заняли последнее место). Место занимают `new`, `confirmed`, `arrived` на `bookings.slot_minutes(minutes)`. Запись закрыта, если `booking_on = 0`, мойка на паузе или подписка истекла.
- Страница записи ставит `g.site` (тема, часовой пояс), не `g.tenant`. Тема страницы — тема мойки. Владелец (своя сессия) видит сверху панель с кружками тем: POST в `/app/settings/theme` с `next=/book/...`.
- Дни на странице записи переключаются через CSS `:has(#dN:checked) #tN` (работает без JS), JS только пересчитывает цены и итог и запоминает имя/телефон в `localStorage`.
- Услугу без цены для выбранного типа авто записать онлайн нельзя: на странице она серая (`disabled`), сервер тоже отказывает. В приложении такую услугу выбрать можно (цену владелец вводит сам).
- Повторная отправка любой формы в течение 10 с блокируется в `app.js` (двойное нажатие на медленном интернете добавляло машину/запись дважды).
- Страница визита шлёт `status_was`: если владелец не трогал статус, сохраняется текущий статус из базы (нажатие Ready на другом телефоне не откатывается). «Collected» не трогает отменённые визиты. Удаление визита возвращает его запись в `new`/`confirmed`.
- Одна машина (по `plate_key`) не может быть на доске дважды (`queries.on_board`): «New car» и смена номера на странице визита отказывают, поиск по номеру пишет «Already on the board · Open it».
- Скан диска: JS (`app.js`, конец секции формы машины) берёт `BarcodeDetector` браузера, если он умеет `pdf417`, иначе грузит `static/vendor/barcode-detector.js` (только по нажатию). Текст штрихкода уходит в `GET /app/disc?code=`, разбирает его `disc.parse` (сервер, покрыто тестами). Якорь разбора — описание и цвет на двух языках (`Hatch back / Luikrug`, `White / Wit`), номер авто — за два поля до описания. Камера работает только по HTTPS (или localhost), без неё кнопка скрыта. Для wasm в CSP стоит `'wasm-unsafe-eval'`.
- Формат диска взят по памяти и из описаний: **проверить на настоящем диске** (если не разберётся — сканер пишет «Couldn't read this disc»).
- Темы: цвета только через токены (`--bg`, `--card`, `--accent`, `--blue` = «моется», `--wa` = «готово» и т. д.). `tenants.theme = ''` значит тема по умолчанию. Выбор посетителя на лендинге (cookie `theme`) копируется в новую мойку и демо. Тема переключается **без перезагрузки** (иначе страница прыгала): `app.js` ловит формы `form[data-look]`, шлёт POST с `X-Requested-With: fetch`, заранее грузит CSS и шрифты темы, подменяет `<link id="look-css">` и держит нажатую кнопку на месте. Включать CSS через `sheet.media`, не атрибут `media` (Chrome на кадр показывает страницу без темы). Без JS работает обычная форма. После правок UI смотреть экран **во всех 5 темах** на 390px (у тем разные шрифты, скругления и ширина текста).

## Особенности облачной песочницы Claude Code
- Системный `pip install flask` падает (конфликт debian-пакета blinker) → ставить в venv.
- Playwright: `chromium.launch(executable_path='/opt/pw-browsers/chromium')`. Не запускать `playwright install`.
- Docker: демон не запущен, стартовать через `sudo dockerd &`.
- `docker build` в песочнице не доверяет прокси-сертификату. Собирать копию Dockerfile, в которой pip-шаг заменён на `RUN --mount=type=secret,id=ca PIP_CERT=/run/secrets/ca pip install ...`, с флагом `--secret id=ca,src=/root/.ccr/ca-bundle.crt`. **Эту правку не коммитить.** На настоящей VM она не нужна.
- Safari и Firefox (Playwright для них не ставить): `sudo apt-get install webkit2gtk-driver xvfb` (WebKitGTK, движок Safari; браузер — `/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1/MiniBrowser --automation`), Firefox — архив с download.mozilla.org + geckodriver с GitHub; гонять через Selenium под `xvfb-run`. Окно уже ~450–500px не сужается.
- wa.me из песочницы недоступен: реальную отправку в WhatsApp проверять только на телефоне.
