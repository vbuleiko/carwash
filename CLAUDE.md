# CLAUDE.md — память проекта CarWashEasy

## Пользователь и как с ним работать
- Пишет по-русски, отвечать по-русски. На этапе планирования просил отвечать **кратко**.
- Требование к продукту: «супер минималистично и удобно». Не раздувать функции, лишнее не добавлять без спроса.
- Бизнес в **ЮАР** (South Africa). Прод: виртуалка **Google Cloud** (Compute Engine), лучше регион `africa-south1` (Йоханнесбург).
- Наш домен — **carwasheasy.co.za**, регистратор **GoDaddy** (DNS-записи правятся там). На 16.10.2026: A `@` → `34.35.130.97` (Google Cloud, `africa-south1`), сайт работает по HTTPS, `www` тоже. Почта — см. раздел «Почта».
- Перед большими задачами пользователь хочет, чтобы сначала задавались уточняющие вопросы.

## Продукт
Автомойки в ЮАР ведут учёт на бумаге: мойщик записывает на листке марку, номер авто и телефон клиента.
CarWashEasy заменяет листок: машину записали → назначили мойщиков → нажали **Ready** → в WhatsApp уходит «машина готова».
Модель — SaaS-подписка для моек. Название **CarWashEasy** (решение 16.10.2026, было Washbook; меняется через `APP_NAME`). Внутренние имена остались старыми, чтобы не трогать живой сервер: файл базы `washbook.db`, бэкапы `washbook-*.db.gz`, ресурсы Google Cloud в README.

## Архитектура
Python 3.12 · Flask 3.1 · SQLite (WAL) · серверные Jinja-шаблоны + один `static/app.js` · без внешних CDN.
Прод: Docker (gunicorn `--preload`, 2 воркера) + контейнер `notify` (тот же образ, `flask --app app notify`) + Caddy (автоматический HTTPS). Данные в томе `/data` (`washbook.db`, `secret_key`).

### Модель данных
`tenants` (мойка) → `car_types`, `services`, `prices(service_id, car_type_id)`, `washers`, `vehicles` (уникальны по `tenant_id + plate_key`) → `visits` → `visit_services` и `visit_washers`.
`tenants` → `bookings` (`slot_at` в UTC, `minutes` — время услуг на момент записи, `status`: `new → confirmed → arrived`, плюс `cancelled` и `cancelled_by` = `owner`/`customer`; `visit_id` после «Arrived»; `code` — для ссылки клиента) → `booking_services`. У `services` есть `minutes` (сколько запись держит место).
Настройки записи в `tenants`: `slug` (уникальный, адрес `/book/<slug>`), `domain` (уникальный, свой адрес мойки, `''` = нет), `address`, `hours` (JSON на 7 дней с понедельника, `''` = по умолчанию), `slot_capacity`, `booking_on`, `msg_booking`, `msg_cancel`.
Убранные колонки (оплата мойщиков) удаляются из старых баз через `db.DROPPED_COLUMNS`.
Мойка без владельца (`queries.is_prospect`): `is_demo = 0` и `email = NULL` — заведена в `/admin`, чтобы показать владельцу сайт; войти в неё нельзя.
Без `tenant_id`-фильтра (служебные): `errors` (ошибки 500: путь, мойка, `place` = последний кадр в `app/`, трассировка; хранятся 30 дней), `mails_sent` (`signup:<id>:<created_at>`, `report:<дата>` — чтобы письмо не ушло дважды), `rate_hits`.

### Соглашения (важно соблюдать)
- **Каждый запрос фильтруется по `tenant_id`.** Для чужих id — 404. Есть тест `test_car_wash_cannot_see_another_car_wash`.
- Деньги хранятся **в центах** (int). Вывод: фильтр `money` → `R1,234` / `R120.50`. В инпутах — фильтр `amount`.
- Время: **UTC-строки `YYYY-MM-DD HH:MM:SS`** (`utils.ts()`). В шаблонах фильтр `local` переводит в пояс мойки (по умолчанию `Africa/Johannesburg`).
- Телефоны хранятся международными цифрами без `+` (`27821234567`) через `normalize_phone`. Номер авто сравнивается по `plate_key` (только A-Z0-9).
- Статусы визита: `queued → washing → ready → collected`, плюс `cancelled`. Метки времени при смене статуса выставляет `queries.status_updates` (при откате вперёд лежащие поля обнуляются).
- Скорость мойщика — среднее отношение его времени к обычному времени на ту же работу (набор услуг + тип авто). Учитываются мойки от 3 до 300 минут; показывается, если у мойщика не меньше 3 таких моек.
- Лояльность считается **по номеру авто**: `loyalty_every = 6` значит, после 5 платных шестая бесплатна; `0` — выключено.
- Все POST-запросы требуют CSRF: поле `csrf` в форме или заголовок `X-CSRF`. JS-запросы шлют `X-Requested-With: fetch` и получают JSON вместо редиректа.
- Вход: в сессии лежат `tenant_id` **и** `key` = `tenants.session_key`, `owner.load_tenant` сверяет их (id удалённых демо SQLite выдаёт заново — без ключа старая cookie открыла бы чужую мойку). Смена пароля и сброс в `/admin` меняют ключ → остальные устройства выходят. Новый вход — только через `public._start_session` / `queries.session_key`.
- Числа из форм (id, проценты) проверять `utils.is_number` (только цифры, до 9 знаков), деньги — `parse_money` (до R9 999 999.99). Иначе 500 от SQLite.
- Лимиты (`security.limiter`) хранятся в таблице `rate_hits`, общие для всех воркеров gunicorn.
- Письма шлёт только контейнер `notify` (веб-приложение SMTP не трогает): раз в минуту `notify.tick` — регистрации за последние сутки, которых нет в `mails_sent`, и после 22:00 отчёт за сутки 22:00–22:00. Сначала отправка, потом отметка; ошибка SMTP — повтор через минуту. Если отчёт не собрался, уходит письмо с трассировкой. Демо в отчёте — только числом. SMTP с проверкой сертификата (587 STARTTLS, 465 SSL). `MAIL_FROM` по умолчанию = `SMTP_USER`, если это адрес (Gmail шлёт только от себя; адрес `@carwasheasy.co.za` через Gmail не пройдёт DMARC `p=quarantine`), иначе `noreply@<DOMAIN>`. `db.init_db` мигрирует под `BEGIN IMMEDIATE`: оба контейнера стартуют одновременно.
- Кнопка «Ready» — это `<a href="wa.me..." target="_blank" data-mark="/app/visit/<id>/ready">`. JS отправляет POST и перезагружает доску. В демо (`data-demo="1"` на body) вместо открытия WhatsApp показывается превью.
- Мойки без владельца (решение 18.10.2026): `/admin` → *Car washes that haven't signed up*, по строке `Name | Address | City | WhatsApp | Google Maps link` (до 50 за раз; строка с именем уже заведённой мойки обновляет её непустые поля). Ссылка — в `tenants.maps_url`, по ней кнопка «Open in Google Maps» на сайте (без неё — поиск по названию и адресу, Google показывает список). Точная ссылка на карточку — `https://maps.google.com/?cid=<число>`: второе hex-число из `!1s0x…:0x…` в адресе места, в десятичном виде. Стартовый прайс, `paid_until` на `admin.PROSPECT_DAYS` (365) вперёд — чтобы запись не закрылась, пока идут переговоры. Сайт — `/site/<slug>` (тот же `site/website.html`, `preview=True` у мойки без владельца): сверху полоса из `site/_top.html` («Made for … · free for 60 days», 5 тем: POST `/theme` с `next`, тема посетителя в cookie; `themes.current()` для такой мойки берёт cookie раньше темы мойки, и на её странице записи тоже; «Make it mine →»), на сайте блок «For the owner» (что получает, цена, **Make it mine** и **See your app**). `noindex` на сайте и странице записи. **Make it mine** (решение 21.10.2026) — `/site/<slug>/claim`: WhatsApp (заполнен из мойки), email, пароль → `email`, тема `themes.current()`, пилот `PILOT_DAYS`, `created_at` = сейчас (письмо о регистрации и строка в отчёте), новый `session_key`, сразу вход. `UPDATE … WHERE email IS NULL` — двое одну мойку не заберут. Место занимают `new`, `confirmed`, `arrived` на `bookings.slot_minutes(minutes)`. Запись закрыта, если `booking_on = 0`, мойка на паузе или подписка истекла.

Ссылку на страницу записи давать только через `site.page_url` (`https://<domain>/` или `/book/<slug>`). HTTPS для адресов моек: Caddy on-demand, разрешение — `GET /tls-check?domain=` (200 только для сохранённых в `/admin`). ## Особенности облачной песочницы Claude Code
- Системный `pip install flask` падает (конфликт debian-пакета blinker) → ставить в venv.
- Playwright: `chromium.launch(executable_path='/opt/pw-browsers/chromium')`. Не запускать `playwright install`.
- Docker: демон не запущен, стартовать через `sudo dockerd &`.
- `docker build` в песочнице не доверяет прокси-сертификату. Собирать копию Dockerfile, в которой pip-шаг заменён на `RUN --mount=type=secret,id=ca PIP_CERT=/run/secrets/ca pip install ...`, с флагом `--secret id=ca,src=/root/.ccr/ca-bundle.crt`. **Эту правку не коммитить.** На настоящей VM она не нужна.
- Safari и Firefox (Playwright для них не ставить): `sudo apt-get install webkit2gtk-driver xvfb` (WebKitGTK, движок Safari; браузер — `/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1/MiniBrowser --automation`), Firefox — архив с download.mozilla.org + geckodriver с GitHub; гонять через Selenium под `xvfb-run`. Окно уже ~450–500px не сужается.
- wa.me из песочницы недоступен: реальную отправку в WhatsApp проверять только на телефоне.

DNS в GoDaddy: MX `@` → `mx1.improvmx.com` (10) и `mx2.improvmx.com` (20), TXT `@` = `v=spf1 include:spf.improvmx.com ~all`, `_dmarc` от GoDaddy (`p=quarantine`). SPF-запись должна оставаться одна: новые `include:` дописывать в неё.
- **Отправка** (только контейнер `notify`, письма о регистрациях и отчёт в 22:00): `smtp.gmail.com:587`, STARTTLS, вход отдельным Gmail **v.buleiko1@gmail.com** по **паролю приложения** (у аккаунта включена 2-Step Verification — без неё страница App passwords пишет «not available for your account»). Отправитель = `SMTP_USER` (`MAIL_FROM` не задан), получатель `NOTIFY_EMAIL=admin@carwasheasy.co.za` → ImprovMX → основной Gmail.
- В `.env` на сервере: `NOTIFY_EMAIL`, `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_USER=v.buleiko1@gmail.com`, `SMTP_PASSWORD` (16 букв без пробелов). Пароль только там — в чат и в репозиторий не просить и не писать.
- Почему так: SMTP у ImprovMX только на Premium ($9/мес), Resend заводить не стали. Отправлять от `@carwasheasy.co.za` через Gmail нельзя: Gmail не подпишет домен, DMARC `p=quarantine` отправит письмо в спам. Свой основной Gmail отправителем не ставить: письмо, вернувшееся через пересылку в тот же ящик, Gmail прячет в «Отправленные».
- Проверка: `sudo docker compose exec notify flask --app app report` → «Sent to admin@carwasheasy.co.za.»; проблемы — `sudo docker compose logs notify --tail 30`. `535 Username and Password not accepted` = пароль приложения неверный или отозван (он слетает при смене пароля Google-аккаунта).
- Не настроено: ответы от имени `admin@` из Gmail («Send mail as»). Через Gmail SMTP такие письма тоже не пройдут DMARC домена — если понадобится писать владельцам моек с `admin@`, нужен SMTP с подписью домена (ImprovMX Premium или Resend + DKIM в GoDaddy).
